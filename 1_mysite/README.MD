## DPITS‑CMS — Django‑сайт с новостями, портфолио, отзывами и тикет‑системой

**DPITS‑CMS** — это многостраничный сайт на Django с разделами:
новости, портфолио, отзывы, пользовательские аккаунты и гибкими
настройками сайта через админ‑панель.

Ниже приведено **подробное описание всех ключевых файлов и модулей проекта**,
а также объяснение их работы **на русском языке**.

> В описание сознательно **не включены автоматически сгенерированные файлы**
> (папки `__pycache__`, миграции, собранная статика `staticfiles/` и т.п.), так как
> они не редактируются вручную.

## 1. Общая структура проекта

### Корневые файлы

- **`manage.py`**  
  Стандартная точка входа Django‑проекта. Запускает сервер разработки,
  применяет миграции, создает суперпользователя и т.д.
  
  **Строки кода:**
  - `os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'mysite.settings')` — устанавливает модуль настроек Django
  - `execute_from_command_line(sys.argv)` — выполняет команды Django из командной строки

- **`requirements.txt`**  
  Список зависимостей проекта (Django, CKEditor, Jazzmin и т.д.)

### Пакет `mysite/` (корневой проект)

- **`__init__.py`**  
  Пометка каталога как Python‑пакета. Пустой файл, необходим для импорта модулей.

- **`settings.py`**  
  Все настройки проекта (БД, приложения, статика, логирование, CKEditor, Jazzmin и т.д.).
  
  **Основные секции:**
  - `BASE_DIR` — базовая директория проекта
  - `SECRET_KEY` — секретный ключ для криптографии (⚠️ в продакшене должен быть в переменных окружения)
  - `DEBUG` — режим отладки (⚠️ в продакшене должно быть `False`)
  - `ALLOWED_HOSTS` — список разрешенных хостов
  - `INSTALLED_APPS` — список установленных приложений
  - `MIDDLEWARE` — список промежуточного ПО
  - `DATABASES` — настройки базы данных (SQLite для разработки)
  - `STATIC_URL`, `STATIC_ROOT`, `MEDIA_URL`, `MEDIA_ROOT` — настройки статики и медиа
  - `LOGGING` — настройки логирования (файлы в папке `logs/`)
  - `JAZZMIN_SETTINGS` — настройки улучшенной админ-панели
  - `CKEDITOR_5_CONFIGS` — настройки текстового редактора

- **`urls.py`**  
  Корневая маршрутизация: подключает `admin/`, `news/`, `portfolio/`, `reviews/`, `accounts/` и `main/`.
  
  **Маршруты:**
  - `path("admin/", admin.site.urls)` — админ-панель Django
  - `path("ckeditor5/", include("django_ckeditor_5.urls"))` — маршруты для CKEditor 5
  - `path("", include("main.urls"))` — главная страница и основные маршруты
  - `path("news/", include("news.urls"))` — маршруты для новостей
  - `path("portfolio/", include("portfolio.urls"))` — маршруты для портфолио
  - `path("reviews/", include("reviews.urls"))` — маршруты для отзывов
  - `path("accounts/", include("accounts.urls"))` — маршруты для аккаунтов
  - `path("files/", include("files.urls"))` — маршруты для управления файлами
  
  **Обработчики ошибок:**
  - `handler404 = "main.views.custom_404_view"` — кастомная страница 404
  - `handler500 = "main.views.custom_500_view"` — кастомная страница 500

- **`wsgi.py`** / **`asgi.py`**  
  Точки входа для WSGI/ASGI‑серверов (продакшн‑запуск).

- **`passenger_wsgi.py`**  
  Специальный файл для запуска на хостинге Beget/Passenger.

## 2. Подробное описание файлов

### Приложение `main/` — "ядро" сайта

#### `apps.py`
Регистрация приложения `main` и его человекочитаемое имя.

**Содержимое:**
- `class MainConfig(AppConfig)` — класс конфигурации приложения
- `name = 'main'` — имя приложения
- `verbose_name = 'Главное'` — человекочитаемое имя для админки

#### `models.py`
Модели базы данных для приложения main.

**Модели:**

1. **`SingletonModel`** (абстрактная модель)
   - Абстрактная модель для создания singleton-объектов (только одна запись)
   - `save()` — переопределяет сохранение, всегда устанавливает `pk = 1`
   - `load()` — возвращает единственный экземпляр, создавая его при необходимости

2. **`SiteSettings`** (наследуется от `SingletonModel`)
   - Глобальные настройки сайта
   - Поля: контакты (телефоны, email, адрес), брендинг (логотип, слоган), соцсети, SEO, статус "сайт закрыт"
   - Методы: `clean()` — валидация данных перед сохранением

3. **`Page`**
   - Пользовательские страницы с SEO и навигацией
   - Поля: заголовок, slug, контент, флаги видимости, порядок отображения, SEO-поля
   - Методы:
     - `get_absolute_url()` — возвращает URL страницы
     - `get_previous_page()` / `get_next_page()` — находит соседние страницы
     - `display_title` — свойство для получения заголовка для отображения

4. **`ManagedFile`**
   - Управление файлами через админку Django
   - Поля: имя, путь, категория, описание, содержимое, кодировка, флаги активности и авто-бэкапа
   - Методы:
     - `create_backup()` — создает резервную копию файла
     - `clear_file()` — очищает содержимое файла
     - `delete_file_from_disk()` — удаляет файл с диска
     - `refresh_file_info()` — обновляет информацию о файле
     - `get_backup_list()` — возвращает список резервных копий

#### `views.py`
Представления (контроллеры) для приложения main.

**Классы и функции:**

1. **`MaintenanceMixin`**
   - Миксин для проверки статуса обслуживания сайта
   - `dispatch()` — перехватывает запрос и проверяет, не закрыт ли сайт

2. **`BaseView`** (наследуется от `TemplateView`)
   - Базовый класс для всех представлений
   - `get_context_data()` — добавляет общие данные контекста (настройки сайта, SEO)

3. **`IndexView`** (наследуется от `MaintenanceMixin`, `BaseView`)
   - Главная страница сайта
   - `get_context_data()` — добавляет рекомендуемые страницы и последние новости
   - Использует кэширование (`cache_page(60 * 15)`) на 15 минут

4. **`PageDetailView`** (наследуется от `MaintenanceMixin`, `DetailView`)
   - Просмотр отдельной страницы
   - `get_queryset()` — возвращает только активные страницы
   - `get_context_data()` — добавляет SEO-данные и ссылки на предыдущую/следующую страницы
   - Использует кэширование (`cache_page(60 * 10)`) на 10 минут

5. **`ContactView`**, **`AboutView`**, **`ProfileView`**
   - Информационные страницы (контакты, о нас, профиль)
   - `ProfileView` требует аутентификации пользователя

6. **`LogStatsView`** (наследуется от `MaintenanceMixin`, `BaseView`)
   - Страница статистики лог-файлов
   - Доступна только для администраторов и персонала (`is_staff`)
   - Отображает:
     - Информацию о файле debug.log (размер, количество строк, дата изменения)
     - Статистику по категориям (ERROR, WARNING, INFO, DEBUG, OTHER)
     - Последние 50 строк лога для предпросмотра
   - Поддерживает очистку лог-файла через POST-запрос
   - Использует функции из модуля `log_utils.py`

7. **`custom_404_view`**, **`custom_500_view`**
   - Кастомные страницы ошибок 404 и 500
   - Отображают настройки сайта и понятные сообщения об ошибках

#### `admin.py`
Регистрация моделей в админке Django.

**Содержимое:**
- Регистрация `SiteSettings`, `Page`, `ManagedFile`
- Действия по работе с файлами (очистка, бэкапы)

#### `signals.py`
Сигналы Django для очистки кэша при изменении настроек/страниц/файлов.

**Сигналы:**
- `post_save` для `SiteSettings` — очищает кэш настроек сайта
- `post_save` / `post_delete` для `Page` — очищает кэш страниц и меню
- `post_save` / `post_delete` для `ManagedFile` — очищает кэш файлов

#### `context_processors.py`
Контекстные процессоры для добавления данных в шаблоны.

**Функции:**
- `site_settings()` — добавляет настройки сайта в каждый шаблон (с кэшированием)
- `menu_items()` — добавляет пункты меню (с кэшированием)
- `sidebar_data()` — добавляет данные сайдбара (последние новости, работы, отзывы)
- `seo_context()` — добавляет базовые SEO-данные

#### `log_utils.py`
Утилиты для работы с лог-файлами.

**Функции:**

1. **`get_log_file_path()`**
   - Получает абсолютный путь к файлу debug.log
   - Создает директорию logs/, если её нет
   - Создает пустой файл debug.log, если его нет

2. **`count_total_lines(log_file_path=None)`**
   - Подсчитывает общее количество строк в лог-файле
   - Возвращает целое число

3. **`count_lines_by_category(log_file_path=None)`**
   - Подсчитывает количество строк по категориям (ERROR, WARNING, INFO, DEBUG, OTHER)
   - Анализирует каждую строку на наличие маркеров уровня логирования
   - Возвращает словарь с количеством по каждой категории

4. **`get_log_file_info(log_file_path=None)`**
   - Получает полную информацию о лог-файле
   - Включает: размер, количество строк, категории, дату изменения
   - Возвращает словарь с метаданными файла

5. **`get_recent_log_lines(count=50, log_file_path=None)`**
   - Получает последние N строк из лог-файла
   - Используется для предпросмотра логов в интерфейсе
   - Возвращает список строк

6. **`clear_log_file(log_file_path=None, create_backup=True)`**
   - Очищает содержимое лог-файла
   - Перед очисткой создает резервную копию (если включено)
   - Возвращает кортеж (success: bool, message: str)

7. **`_format_file_size(size_bytes)`** (приватная функция)
   - Преобразует размер файла из байтов в читаемый формат (B, KB, MB, GB, TB)
   - Используется для отображения размера файла

8. **`_create_backup(log_file_path)`** (приватная функция)
   - Создает резервную копию файла перед операциями
   - Сохраняет копию в директории backups/ рядом с исходным файлом
   - Имя файла включает временную метку

#### `urls.py`
Маршруты приложения main.

**Маршруты:**
- `""` — главная страница (`IndexView`)
- `"page/<slug:slug>/"` — детальная страница (`PageDetailView`)
- `"contacts/"` — страница контактов (`ContactView`)
- `"about/"` — страница "О нас" (`AboutView`)
- `"profile/"` — страница профиля (`ProfileView`)
- `"log-stats/"` — статистика лог-файлов (`LogStatsView`, только для администраторов)

### Приложение `news/` — новости

#### `models.py`
Модели для новостей.

**Модели:**

1. **`NewsCategory`**
   - Категории новостей
   - Поля: название, slug, изображение, описание, SEO-поля, флаги видимости и активности
   - Методы:
     - `save()` — автоматически создает slug из названия
     - `get_absolute_url()` — возвращает URL категории

2. **`News`**
   - Новостные статьи
   - Поля: заголовок, slug, категория, изображение, SEO-поля, краткое описание, содержание, счетчик просмотров
   - Методы:
     - `save()` — автоматически создает slug из заголовка
     - `get_absolute_url()` — возвращает URL новости
     - `increment_views()` — увеличивает счетчик просмотров (оптимизировано: сохраняет только поле `views`)

#### `views.py`
Представления для новостей.

**Функции:**

1. **`news_list()`**
   - Список всех активных новостей
   - Использует пагинацию (20 новостей на страницу)
   - **ОПТИМИЗАЦИЯ:** `select_related("category")` для уменьшения запросов к БД
   - **ОПТИМИЗАЦИЯ:** кэширование категорий и последних новостей

2. **`news_detail()`**
   - Детальная страница новости
   - Увеличивает счетчик просмотров
   - Показывает похожие новости из той же категории
   - **ОПТИМИЗАЦИЯ:** `select_related("category")` для оптимизации запросов

3. **`news_by_category()`**
   - Новости определенной категории
   - Использует пагинацию
   - **ОПТИМИЗАЦИЯ:** `select_related("category")` и кэширование

4. **`news_search()`**
   - Поиск новостей по запросу
   - Поиск по заголовку, краткому описанию и содержанию
   - **ОПТИМИЗАЦИЯ:** `select_related("category")` и расширенный поиск

**ИСПРАВЛЕНО:** Удалена функция `news_by_tag()`, так как в модели `News` нет поля `tags`.

#### `urls.py`
Маршруты для новостей.

**Маршруты:**
- `""` — список новостей (`news_list`)
- `"category/<slug:slug>/"` — новости категории (`news_by_category`)
- `"<slug:slug>/"` — детальная новость (`news_detail`)

#### `context_processors.py`
Контекстный процессор для последних новостей в сайдбаре.

### Приложение `portfolio/` — портфолио и заказы

#### `models.py`
Модели для портфолио.

**Модели:**

1. **`Client`**
   - Профиль клиента
   - Поля: пользователь, компания, телефон, веб-сайт, описание, флаг подтверждения

2. **`PortfolioCategory`**
   - Категории работ портфолио
   - Поля: название, изображение, slug, описание, SEO-поля, порядок отображения
   - Методы:
     - `save()` — автоматически создает slug из названия
     - `works_count()` — количество работ в категории

3. **`PortfolioItem`**
   - Работа портфолио
   - Поля: заголовок, slug, категория, клиент, изображение, описание, технологии, дата проекта, ссылки, статус, SEO-поля, счетчик просмотров
   - Методы:
     - `save()` — автоматически создает slug из заголовка
     - `get_absolute_url()` — возвращает URL работы
     - `get_technologies_list()` — возвращает список технологий
     - `increment_views()` — увеличивает счетчик просмотров

4. **`Order`**
   - Заказ клиента
   - Поля: клиент, название, описание, бюджет, срок выполнения, статус, приоритет, файл требований, заметки
   - Методы:
     - `is_overdue` — проверяет, просрочен ли заказ
     - `get_progress_percentage()` — возвращает процент выполнения заказа

5. **`OrderMessage`**
   - Сообщения по заказу
   - Поля: заказ, пользователь, сообщение, файл, флаг "сообщение администратора"

6. **`PortfolioReview`**
   - Отзывы клиентов о работах
   - Поля: клиент, работа, рейтинг, заголовок, текст, флаг одобрения
   - Методы:
     - `get_star_rating()` — возвращает HTML для отображения звезд рейтинга

#### `views.py`
Представления для портфолио.

**Классы и функции:**

1. **`PortfolioListView`** (наследуется от `ListView`)
   - Список всех работ портфолио
   - Фильтрация по категории
   - **ОПТИМИЗАЦИЯ:** `select_related("category", "client")` для оптимизации запросов
   - **ОПТИМИЗАЦИЯ:** кэширование категорий

2. **`PortfolioDetailView`** (наследуется от `DetailView`)
   - Детальная страница работы
   - Показывает отзывы и похожие работы
   - **ОПТИМИЗАЦИЯ:** `select_related("client", "client__user")` для отзывов
   - **ОПТИМИЗАЦИЯ:** `select_related("category", "client")` для похожих работ

3. **`client_dashboard()`**
   - Личный кабинет клиента
   - Показывает статистику и последние заказы/отзывы
   - **ОПТИМИЗАЦИЯ:** использование агрегации (`Count`) для статистики
   - **ОПТИМИЗАЦИЯ:** `select_related()` для оптимизации запросов

4. **`order_list()`**
   - Список всех заказов клиента
   - Фильтрация по статусу
   - **ОПТИМИЗАЦИЯ:** использование агрегации для статистики

5. **`order_detail()`**
   - Детальная страница заказа
   - Показывает сообщения по заказу
   - **ОПТИМИЗАЦИЯ:** `select_related()` и `prefetch_related()` для сообщений

6. **`create_order()`**, **`create_review()`**
   - Создание нового заказа/отзыва

#### `urls.py`
Маршруты для портфолио.

#### `forms.py`
Формы для заказов, отзывов и профиля клиента.

#### `utils.py`
Вспомогательные функции (например, `custom_upload_to` для загрузки файлов).

### Приложение `accounts/` — пользователи и тикеты

#### `models.py`
Модели для аккаунтов.

**Модели:**

1. **`UserProfile`**
   - Расширенный профиль пользователя
   - Поля: пользователь (OneToOne), телефон, аватар, биография
   - Методы:
     - `get_avatar_url` — возвращает URL аватара или изображение по умолчанию
     - `clean()` — валидация номера телефона

2. **`Ticket`**
   - Тикеты технической поддержки
   - Поля: пользователь, тема, сообщение, статус
   - Статусы: "open" (открыт), "in_progress" (в обработке), "closed" (закрыт)
   - Методы:
     - `is_open` / `is_closed` — свойства для проверки статуса
     - `can_user_access(user)` — проверка прав доступа к тикету

3. **`TicketResponse`**
   - Ответы на тикеты
   - Поля: тикет, пользователь, сообщение, флаг "ответ администрации"
   - Методы:
     - `save()` — автоматически помечает ответы от staff как административные
     - `clean()` — валидация сообщения (не должно быть пустым)

**Сигналы:**
- `create_or_update_user_profile` — автоматически создает профиль при создании пользователя

## 5. Описание функций и методов

### Основные функции и методы

#### `SiteSettings.load()`
Возвращает единственный объект настроек сайта, создавая его при первом обращении.

**Использование:**
```python
settings = SiteSettings.load()
```

#### `Page.get_absolute_url()`
Строит постоянную ссылку на страницу по её `slug`.

**Использование:**
```python
url = page.get_absolute_url()
```

#### `Page.get_previous_page()` / `Page.get_next_page()`
Находит соседние страницы по сортировке (или дате) для навигации "вперед/назад".

**Использование:**
```python
prev_page = page.get_previous_page()
next_page = page.get_next_page()
```

#### `News.increment_views()`
Увеличивает счетчик просмотров новости, сохраняя только поле `views` (оптимизация UPDATE‑запроса).

**Использование:**
```python
news.increment_views()
```

#### `PortfolioItem.increment_views()`
Увеличивает счетчик просмотров работы портфолио.

**Использование:**
```python
portfolio_item.increment_views()
```

#### `Ticket.can_user_access(user)`
Проверка прав доступа к тикету. Пользователь может просматривать тикет, если он является его автором или является сотрудником (staff).

**Использование:**
```python
if ticket.can_user_access(request.user):
    # Показать тикет
```

## 6. Развёртывание и работа на хостинге

### Настройки для продакшена

⚠️ **ВАЖНО:** Перед развертыванием на продакшене необходимо:

1. Изменить `DEBUG = False` в `settings.py`
2. Установить `SECRET_KEY` из переменных окружения
3. Настроить `ALLOWED_HOSTS` с реальными доменами
4. Настроить базу данных (PostgreSQL/MySQL вместо SQLite)
5. Настроить кэширование (Redis/Memcached)
6. Настроить логирование
7. Собрать статику: `python manage.py collectstatic`
8. Применить миграции: `python manage.py migrate`

### Команды для развертывания

```bash
# Активация виртуального окружения
source venv/bin/activate

# Установка зависимостей
pip install -r requirements.txt

# Применение миграций
python manage.py migrate

# Создание суперпользователя
python manage.py createsuperuser

# Сбор статики
python manage.py collectstatic

# Запуск сервера (для разработки)
python manage.py runserver
```

## 7. Логирование и статистика логов

### Хранение логов

Логи сохраняются в папке `logs/`:
- `debug.log` — общие логи (уровень INFO)
- `error.log` — ошибки (уровень ERROR)

Настройки логирования находятся в `settings.py` в секции `LOGGING`.

### Функционал просмотра статистики логов

В приложении `main` реализован функционал для работы с лог-файлами:

#### Страница статистики логов (`/log-stats/`)

Доступна только для администраторов и персонала. Позволяет:

1. **Просмотр информации о файле debug.log:**
   - Полный путь к файлу
   - Размер файла (в байтах и читаемом формате)
   - Общее количество строк
   - Дата последнего изменения

2. **Статистика по категориям:**
   - Количество строк с уровнем ERROR (ошибки)
   - Количество строк с уровнем WARNING (предупреждения)
   - Количество строк с уровнем INFO (информационные)
   - Количество строк с уровнем DEBUG (отладочные)
   - Количество строк других типов (OTHER)

3. **Предпросмотр последних строк:**
   - Отображение последних 50 строк лога
   - Автоматическая подсветка строк по категориям
   - Скролл до последней строки при загрузке

4. **Очистка лог-файла:**
   - Кнопка для очистки содержимого файла
   - Автоматическое создание резервной копии перед очисткой
   - Подтверждение действия перед выполнением

#### Технические детали

- Все функции находятся в модуле `main/log_utils.py`
- Категоризация строк выполняется с помощью регулярных выражений
- Резервные копии сохраняются в `logs/backups/` с временной меткой
- Шаблон страницы: `main/templates/main/log_stats.html`
- Использует анимации и современный дизайн для улучшения UX

#### Безопасность

- Доступ к странице статистики только для пользователей с флагом `is_staff`
- Очистка лог-файла требует подтверждения через JavaScript confirm
- Все операции логируются для аудита
