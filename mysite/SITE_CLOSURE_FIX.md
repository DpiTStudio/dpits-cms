# Решение проблемы с работой ссылок после закрытия сайта

## Проблема
После закрытия сайта (установки галочки "Сайт закрыт" в настройках) и последующего открытия (снятия галочки), ссылки на сайте могут не работать из-за кэширования.

## Решение

### Автоматическое решение (рекомендуется)
Система теперь автоматически очищает весь кэш при изменении настроек сайта. Это означает:

1. **При закрытии сайта**: Установите галочку "Сайт закрыт" в админ-панели → Кэш очистится автоматически
2. **При открытии сайта**: Снимите галочку "Сайт закрыт" → Кэш очистится автоматически

### Использование команды управления (быстрый способ)

Создана специальная команда для управления статусом сайта через терминал:

```bash
# Показать текущий статус сайта
python manage.py toggle_site_status --status

# Открыть сайт для всех пользователей
python manage.py toggle_site_status --open

# Закрыть сайт (режим обслуживания)
python manage.py toggle_site_status --close

# Закрыть сайт с пользовательским сообщением
python manage.py toggle_site_status --close --message "Сайт временно недоступен"

# Переключить статус (открыт ↔ закрыт)
python manage.py toggle_site_status
```

### Ручная очистка кэша (если нужно)

Если по какой-то причине автоматическая очистка не сработала:

1. **Через Django shell**:
```bash
python manage.py shell
```

```python
from django.core.cache import cache
cache.clear()
print("Кэш очищен!")
```

2. **Перезапуск сервера разработки**:
```bash
# Остановите сервер (Ctrl+C)
# Запустите снова
python manage.py runserver
```

## Как работает система

### 1. Проверка статуса сайта
Класс `MaintenanceMixin` в `main/views.py` проверяет статус `site_closed` при каждом запросе:

- Если `site_closed = True` и пользователь НЕ является персоналом → показывается страница обслуживания
- Если `site_closed = False` ИЛИ пользователь является персоналом → сайт работает нормально

### 2. Автоматическая очистка кэша
Сигнал в `main/signals.py` автоматически очищает весь кэш при изменении настроек:

```python
@receiver([post_save, post_delete], sender=SiteSettings)
def clear_site_settings_cache(sender, instance=None, **kwargs):
    cache.clear()  # Очищает весь кэш
```

### 3. Доступ для персонала
Пользователи с флагом `is_staff=True` всегда имеют доступ к сайту, даже когда он закрыт. Это позволяет администраторам проверять работу сайта.

## Внесенные изменения

1. **main/views.py**:
   - Улучшен `MaintenanceMixin.dispatch()` с комментариями о загрузке настроек без кэширования

2. **main/signals.py**:
   - Добавлено логирование при очистке кэша
   - Улучшена документация сигнала

3. **main/management/commands/toggle_site_status.py**:
   - Создана новая команда для управления статусом сайта
   - Автоматическая очистка кэша при изменении статуса
   - Отображение текущего статуса

## Проверка работы

1. Откройте админ-панель: http://127.0.0.1:6678/admin/
2. Перейдите в "Настройки сайта"
3. Установите галочку "Сайт закрыт"
4. Сохраните
5. Откройте сайт в режиме инкогнито → должна показаться страница обслуживания
6. Снимите галочку "Сайт закрыт"
7. Сохраните
8. Обновите страницу → сайт должен работать нормально

## Дополнительная информация

### Страница обслуживания
Шаблон: `main/templates/main/site_closed.html`

Показывает:
- Логотип сайта
- Сообщение о техническом обслуживании

### Кэширование страниц
Некоторые страницы кэшируются на 15 минут (`@cache_page(60 * 15)`), но при изменении настроек сайта весь кэш очищается автоматически, поэтому изменения вступают в силу немедленно.

## Устранение неполадок

### Проблема: Сайт все еще показывает страницу обслуживания после открытия

**Решение**:
1. Проверьте статус: `python manage.py toggle_site_status --status`
2. Откройте сайт: `python manage.py toggle_site_status --open`
3. Очистите кэш браузера (Ctrl+Shift+Del)
4. Откройте сайт в режиме инкогнито

### Проблема: Изменения не применяются

**Решение**:
1. Убедитесь, что сервер разработки запущен
2. Проверьте логи сервера на наличие ошибок
3. Перезапустите сервер разработки
4. Очистите кэш вручную: `python manage.py shell` → `from django.core.cache import cache; cache.clear()`

### Проблема: Нужно проверить сайт, но он закрыт

**Решение**:
1. Войдите в админ-панель
2. Ваш пользователь должен иметь флаг `is_staff=True`
3. Персонал всегда имеет доступ к закрытому сайту

## Контакты для поддержки

Если проблема не решена, проверьте:
- Логи сервера разработки
- Настройки кэширования в `settings.py`
- Правильность подключения сигналов в `main/apps.py`
