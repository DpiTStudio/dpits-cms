## DPITS‑CMS — Django‑сайт с новостями, портфолио, отзывами и тикет‑системой

**DPITS‑CMS** — это многостраничный сайт на Django с разделами:
новости, портфолио, отзывы, пользовательские аккаунты, обратная связь и гибкими
настройками сайта через админ‑панель.

Ниже приведено **подробное описание всех ключевых файлов и модулей проекта**,
а также объяснение их работы **на русском языке**.

> В описание сознательно **не включены автоматически сгенерированные файлы**
> (папки `__pycache__`, миграции, собранная статика `staticfiles/` и т.п.), так как
> они не редактируются вручную.

## 1. Общая структура проекта

### Корневые файлы

- **`manage.py`**  
  Стандартная точка входа Django‑проекта. Запускает сервер разработки,
  применяет миграции, создает суперпользователя и т.д.
  
  **Строки кода:**
  - `os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'mysite.settings')` — устанавливает модуль настроек Django
  - `execute_from_command_line(sys.argv)` — выполняет команды Django из командной строки

- **`requirements.txt`**  
  Список зависимостей проекта (Django, CKEditor, Jazzmin, Pillow и т.д.)

### Пакет `mysite/` (корневой проект)

- **`__init__.py`**  
  Пометка каталога как Python‑пакета.

- **`settings.py`**  
  Все настройки проекта.
  
  **Основные секции:**
  - `INSTALLED_APPS` — подключенные приложения (`main`, `news`, `portfolio`, `reviews`, `accounts`, `feedback`, `django_ckeditor_5`, `captcha`, `jazzmin` и др.)
  - `MIDDLEWARE` — промежуточное ПО (включая защиту от CSRF, сессии, аутентификацию)
  - `DATABASES` — настройки БД (SQLite)
  - `LOGGING` — настройки логирования (файлы `debug.log`, `error.log`)
  - `JAZZMIN_SETTINGS` — настройки UI админ-панели

- **`urls.py`**  
  Корневая маршрутизация URL.
  
  **Маршруты:**
  - `admin/` — Админ-панель
  - `ckeditor5/` — Редактор контента
  - `captcha/` — Капча
  - `news/` — Новости
  - `portfolio/` — Портфолио
  - `reviews/` — Отзывы
  - `accounts/` — Аккаунты
  - `feedback/` — Обратная связь
  - `/` — Главная и остальные страницы (приложение `main`)

## 2. Подробное описание файлов

### Приложение `main/` — "ядро" сайта

Отвечает за главную страницу, статические страницы, настройки сайта и логирование.

#### `models.py`
- **`SingletonModel`**: Абстрактная модель для таблиц с одной записью.
- **`SiteSettings`**: Глобальные настройки (контакты, лого, соцсети, SEO). Использует `SingletonModel`.
- **`Page`**: Динамические страницы с SEO-настройками и управлением из админки.
- **`ManagedFile`**: Модель для управления физическими файлами на сервере через админку. Содержит методы для бэкапа (`create_backup`), очистки (`clear_file`) и удаления.

#### `views.py`
- **`MiddlewareMixin`**: Проверяет, не закрыт ли сайт на обслуживание.
- **`IndexView`**: Главная страница (кэшируется на 15 мин).
- **`PageDetailView`**: Отображение динамических страниц по slug.
- **`ContactView`, `AboutView`**: Статические страницы.
- **`ProfileView`**: Профиль пользователя (редирект на логин, если не вошел).
- **`LogStatsView`**: Страница статистики логов (только для staff). Показывает размер логов, статистику по уровням ошибок, последние строки.
- **`custom_404_view`, `custom_500_view`**: Кастомные страницы ошибок.

#### `log_utils.py` (Новое)
Утилиты для работы с логами:
- `get_log_file_path()`: Путь к логам.
- `count_total_lines()`, `count_lines_by_category()`: Статистика строк.
- `get_recent_log_lines()`: Чтение "хвоста" файла.
- `clear_log_file()`: Очистка с бэкапом.

#### `admin_files.py`
Специализированная админ-панель для `ManagedFile`. Позволяет управлять текстовыми и бинарными файлами, создавать бэкапы и очищать их содержимое прямо из браузера.

### Приложение `news/` — Новости

#### `models.py`
- **`NewsCategory`**: Категории новостей со слагами.
- **`News`**: Новостные статьи. Поля: заголовок, категория, изображение, текст, счетчик просмотров (`views`).
  - Метод `increment_views()`: Оптимизированный инкремент счетчика (update только одного поля).

#### `views.py`
- **`news_list`**: Список новостей с пагинацией и кэшированием.
- **`news_detail`**: Просмотр новости, увеличивает счетчик просмотров.
- **`news_search`**: Поиск по заголовку и тексту.

---

### Приложение `portfolio/` — Портфолио и Заказы

#### `models.py`
- **`Client`**: Расширение пользователя для клиентов (компания, телефон).
- **`PortfolioCategory`**: Категории работ.
- **`PortfolioItem`**: Работы портфолио (изображения, технологии, описание).
- **`Order`**: Заказы клиентов (бюджет, сроки, статус, файлы).
- **`OrderMessage`**: Чат внутри заказа (сообщения и файлы).
- **`PortfolioReview`**: Отзывы к конкретным работам.

#### `views.py`
- **`PortfolioListView`**: Галерея работ с фильтром по категориям.
- **`client_dashboard`**: Личный кабинет заказчика (статистика заказов).
- **`order_detail`**: Страница заказа с чатом.

---

### Приложение `reviews/` — Отзывы пользователей

#### `models.py`
- **`Review`**: Отзыв о сайте. Статусы: `pending`, `approved`, `rejected`.
  - Валидация телефона и email.

#### `views.py`
- **`review_list`**: Список одобренных отзывов.
- **`add_review`**: Форма добавления (требует модерации). Использует анимации при отправке.

---

### Приложение `feedback/` — Обратная связь (Новое описание)

Модуль для связи пользователей с администрацией.

#### `models.py`
- **`FeedbackMessage`**: Сообщение от пользователя.
  - Поля: тема, email, сообщение, статус (новое/прочитано), дата.
  - При сохранении может отправлять уведомление на почту админа (см. сигналы/метод save).

#### `views.py`
- **`FeedbackCreateView`**: Форма создания сообщения. Защищена капчей.
- **`FeedbackListView`**: Список отправленных пользователем сообщений (история обращений).

#### `forms.py`
- **`FeedbackForm`**: Форма с полями `subject`, `message` и `captcha`.

---

### Приложение `accounts/` — Аккаунты и Тикеты

#### `models.py`
- **`UserProfile`**: Профиль (аватар, телефон). Связан 1-к-1 с `User`.
- **`Ticket`**: Тикет техподдержки. Статусы: Открыт, В работе, Закрыт.
- **`TicketResponse`**: Ответы в тикете.

#### `views.py`
- **`register`, `login`, `profile_view`**: Стандартные действия.
- **`ticket_list`, `ticket_detail`, `create_ticket`**: Система тикетов.

## 4. Оптимизации и исправления

1. **База данных**:
   - Повсеместное использование `select_related` и `prefetch_related` в `views.py` всех приложений для устранения проблемы "N+1 запросов".
   - Индексы в моделях (подразумеваются Django по умолчанию для FK и slugs).

2. **Кэширование**:
   - `main/views.py`: Кэширование главной страницы (`cache_page(60 * 15)`).
   - `context_processors.py`: Кэширование меню и настроек сайта.

3. **Код**:
   - Удален мертвый код (например, `news_by_tag` в `news/views.py`).
   - Исправлены пути к CSS в админке (`main/admin.py`).
   - Добавлена обработка ошибок загрузки файлов.

## 5. Описание функций и методов

### `main.log_utils`
- **`count_lines_by_category(path)`** -> `dict`: Парсит файл лога, ищет подстроки `[ERROR]`, `[WARNING]` и возвращает словарь счетчиков.

### `main.models.ManagedFile`
- **`create_backup()`**:
  1. Проверяет существование файла.
  2. Создает папку `backups/` в директории файла.
  3. Копирует файл с добавлением timestamp в имя.
  4. Удаляет старые бэкапы, если их > `max_backups`.

### `news.models.News`
- **`increment_views()`**:
  Выполняет SQL-запрос `UPDATE news_news SET views = views + 1 WHERE id = ...` без загрузки всего объекта и сохранения всех полей (использует `update_fields`).

### `accounts.models.Ticket`
- **`can_user_access(user)`**:
  Возвращает `True`, если `user` — автор тикета или суперюзер/персонал. Иначе `False`.

## 6. Развёртывание

1. **Настройки**:
   В `settings.py` установить `DEBUG = False`, задать `ALLOWED_HOSTS`.
2. **Статика**:
   Выполнить `python manage.py collectstatic`.
3. **Логи**:
   Убедиться, что папка `logs/` доступна для записи веб-сервером.
4. **Запуск**:
   Использовать `gunicorn mysite.wsgi:application` (или аналог).
