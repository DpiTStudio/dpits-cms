## DPITS‑CMS — Django‑сайт с новостями, портфолио, отзывами и тикет‑системой

**DPITS‑CMS** — это многостраничный сайт на Django с разделами:
новости, портфолио, отзывы, пользовательские аккаунты и гибкими
настройками сайта через админ‑панель.

Ниже приведено **общее описание всех ключевых файлов и модулей проекта**,
а также краткое объяснение их работы **на русском языке**.

> В описание сознательно **не включены автоматически сгенерированные файлы**
> (папки `__pycache__`, миграции, собранная статика `staticfiles/` и т.п.), так как
> они не редактируются вручную.

## 1. Общая структура проекта

- **`manage.py`**  
  Стандартная точка входа Django‑проекта. Запускает сервер разработки,
  применяет миграции, создает суперпользователя и т.д.

- **Пакет `mysite/` (корневой проект)**
  - `__init__.py` — пометка каталога как Python‑пакета.
  - `settings.py` — все настройки проекта (БД, приложения, статика, логирование,
    CKEditor, Jazzmin и т.д.).
  - `urls.py` — корневая маршрутизация: подключает `admin/`, `news/`, `portfolio/`,
    `reviews/`, `accounts/` и `main/`.
  - `wsgi.py` / `asgi.py` — точки входа для WSGI/ASGI‑серверов (продакшн‑запуск).
  - `passenger_wsgi.py` — специальный файл для запуска на хостинге Beget/Passenger.

- **Приложение `main/` — “ядро” сайта**
  - `apps.py` — регистрация приложения `main` и его человекочитаемое имя.
  - `models.py` — модели:
    - `SingletonModel` — абстрактная модель‑одиночка (PK всегда `1`).
    - `SiteSettings` — глобальные настройки сайта (контакты, соцсети, SEO,
      статус “сайт закрыт” и т.д.).
    - `Page` — пользовательские страницы с SEO и навигацией (пред/след страница).
    - `ManagedFile` — описание произвольного файла на диске с возможностью
      читать/редактировать/делать бэкапы через админку.
  - `views.py` — представления:
    - `MaintenanceMixin` — проверка, закрыт ли сайт на обслуживание.
    - `BaseView` — базовый класс, подгружает `SiteSettings` и SEO по умолчанию.
    - `IndexView` — главная страница, вывод рекомендуемых страниц и последних новостей.
    - `PageDetailView` — просмотр отдельной страницы (`Page`).
    - `ContactView`, `AboutView`, `ProfileView` — информационные страницы.
    - `custom_404_view`, `custom_500_view` — кастомные страницы ошибок.
  - `admin.py` — регистрация `SiteSettings`, `Page`, `ManagedFile` в админке,
    действия по работе с файлами (очистка, бэкапы и т.п.).
  - `signals.py` — сигналы, очищающие кэш при изменении настроек/страниц/файлов.
  - `context_processors.py` — дополнительные данные в шаблонах:
    настройки сайта, пункты меню, данные сайдбара.
  - `urls.py` — маршруты главной, страниц, контактов, “О нас” и профиля.
  - `templates/main/*.html` — шаблоны страниц раздела `main`.
  - `static/main/css/*.css` — стили для публичных страниц `main`.

- **Приложение `news/` — новости**
  - `models.py`:
    - `NewsCategory` — категории новостей с SEO‑полями и флагами видимости.
    - `News` — новостные статьи с кратким описанием, полным текстом, SEO и счетчиком просмотров.
  - `views.py` — список новостей, фильтрация по категории, детальная новость.
  - `urls.py` — маршруты: список новостей, категория, детальная новость.
  - `templates/news/*.html` — шаблоны списка/детальной новости/категорий.
  - `static/news/css/*.css` — стили для новостного раздела.

- **Приложение `portfolio/` — портфолио и заказы**
  - `models.py`:
    - `Client` — профиль клиента, заказавшего работы.
    - `PortfolioCategory` — категории работ портфолио с SEO‑настройками.
    - `PortfolioItem` — отдельная работа портфолио с описанием, технологиями и ссылками.
    - `Order` — заказ клиента, со статусом, приоритетом, бюджетом и сроками.
    - `OrderMessage` — сообщения по заказу (переписка клиента и админа).
    - `PortfolioReview` — отзывы клиентов о конкретных работах.
  - `views.py` — список/детальная страница работ, форма заявки, просмотр заказов.
  - `forms.py` — формы для заказов, сообщений и т.п.
  - `urls.py` — маршруты для портфолио и заявок.
  - `utils.py` — вспомогательные функции (`custom_upload_to` для загрузки файлов).
  - `templates/portfolio/*.html` — шаблоны списка/детальных страниц/отзывов.
  - `static/portfolio/css/*.css` — стили портфолио.

- **Приложение `reviews/` — отзывы**
  - `models.py`:
    - `Review` — общий отзыв с ФИО, телефоном, email, текстом и статусом модерации.
  - `forms.py` — форма создания/редактирования отзыва.
  - `views.py` — вывод списка отзывов и добавление нового.
  - `urls.py` — маршруты для списка/создания отзыва.
  - `templates/reviews/*.html` — шаблоны раздела отзывов.
  - `static/reviews/*` — стили/изображения для отзывов.

- **Приложение `accounts/` — пользователи и тикеты**
  - `models.py`:
    - `UserProfile` — расширенный профиль (аватар, телефон, bio и т.д.).  
      Сигнал автоматически создает профиль при создании `User`.
    - `Ticket` — тикеты поддержки с пользователем, темой, текстом и статусом.
    - `TicketResponse` — ответы к тикетам, с флагом “ответ администрации”.
  - `forms.py` — регистрация, обновление профиля, смена пароля, тикеты и ответы.
  - `views.py`:
    - Регистрация/выход/смена пароля.
    - Просмотр/редактирование профиля.
    - Список тикетов, создание тикета, детальный просмотр с ответами.
  - `urls.py` — маршруты: регистрация, вход, профиль, тикеты.
  - `backends.py` — собственный бэкенд аутентификации (логин по email/username).
  - `mixins.py` — миксины проверки прав.
  - `signals.py` — обработчики сигналов (создание профиля и т.п.).
  - `utils.py` — вспомогательный код (утилиты для аккаунтов/тикетов).
  - `templates/accounts/*.html` — шаблоны регистрации, логина, профиля, тикетов.
  - `static/accounts/css/*.css` — стили для личного кабинета.

- **Корневая папка `templates/`**
  - `base.html` — общий базовый шаблон сайта.
  - `header.html`, `footer.html`, `sidebar.html`, `hero.html`, `content-section.html` и др. —
    переиспользуемые фрагменты интерфейса.
  - `bg_cont/*.html` — фоновые/контентные блоки для главной и внутренних страниц.

- **Папка `static/`**
  - `css/` — глобальные стили сайта (в т.ч. общие для всех приложений).
  - `js/`:
    - `main.js`, `script.js` — общий фронтенд‑функционал.
    - `admin-file-manager.js` — логика управления файлами в админке.
  - `images/` — логотипы, иконки, фоновые изображения.

- **Папка `media/`**
  - `avatars/` — загружаемые аватары пользователей.
  - `logos/` — логотипы сайта.
  - `news/` — изображения для новостей и категорий.
  - Остальное — загруженные через CKEditor/формы файлы.

- **`logs/`**
  - `debug.log`, `error.log` — файлы логов Django согласно настройкам `LOGGING`.

## 2. Краткое описание основных функций и классов

Ниже — обзор **ключевых функций и методов** (без перечисления
каждой технической строчки кода, но с пояснением логики):

- **`SiteSettings.load()` (класс `SiteSettings`)**  
  Возвращает единственный объект настроек сайта, создавая его при первом обращении.

- **`Page.get_absolute_url()`**  
  Строит постоянную ссылку на страницу по её `slug` (используется в шаблонах и админке).

- **`Page.get_previous_page()` / `Page.get_next_page()`**  
  Находит соседние страницы по сортировке (или дате) для навигации “вперед/назад”.

- **Методы `ManagedFile`** (`create_backup`, `clear_file`, `delete_file_from_disk`,  
  `refresh_file_info`, `get_backup_list` и внутренние `_update_file_info`, `_read_file_content`):
  - читают файл с диска в разных кодировках,
  - определяют MIME‑тип и размер,
  - создают/очищают/удаляют файл,
  - ведут список резервных копий и автоматически чистят старые.

- **`IndexView.get_context_data()`**  
  Добавляет в контекст главной страницы:
  настройки сайта, список рекомендованных страниц, 3 последние новости,
  а также корректный SEO‑заголовок и описание (с обрезкой HTML и длины).

- **`PageDetailView.get_context_data()`**  
  Формирует SEO‑данные для конкретной страницы, а также ссылки на предыдущую/следующую.

- **Кастомные обработчики `custom_404_view` и `custom_500_view`**  
  Рендерят свои шаблоны ошибок с учетом настроек сайта.

- **`NewsCategory.save()` и `News.save()`**  
  Автоматически создают уникальный `slug` на основе имени/заголовка.

- **`News.increment_views()`**  
  Увеличивает счетчик просмотров новости, сохраняя только поле `views`
  (оптимизация UPDATE‑запроса).

- **Модели портфолио (`Client`, `PortfolioCategory`, `PortfolioItem`, `Order`, `OrderMessage`, `PortfolioReview`)**  
  Хранят полную информацию о клиентах, работах, заказах, переписке и рейтингах.
  Методы `get_absolute_url`, `get_technologies_list`, `increment_views` и
  `get_star_rating` используются для формирования ссылок, списков технологий,
  счетчиков просмотров и HTML‑звезд для рейтинга.

- **`UserProfile.get_avatar_url`**  
  Возвращает URL аватара пользователя или путь к картинке по умолчанию,
  если аватар не загружен.

- **Сигнал `create_or_update_user_profile` (в `accounts.models`)**  
  Автоматически создает или обновляет профиль `UserProfile` при сохранении
  объекта `User`, а при ошибке логирует её.

- **`Ticket.is_open` / `Ticket.is_closed` / `Ticket.can_user_access(user)`**  
  Удобные свойства/метод для проверки состояния тикета и прав доступа.

- **`TicketResponse.save()` и `TicketResponse.clean()`**  
  Автоматически отмечает ответы от `staff`‑пользователей как “административные”
  и проверяет, что текст ответа не пустой.

- **Вьюхи `accounts/views.py`**  
  - `register` — регистрация пользователя, создание аккаунта в транзакции,
    автоматический логин и обработка ошибок с логированием.
  - `profile_edit` / `profile_update` — изменение основных данных и расширенного профиля
    (две формы, обернутые в транзакцию).
  - `password_change` — смена пароля с обновлением сессии.
  - `ticket_list` / `ticket_detail` / `create_ticket` — список тикетов,
    просмотр и добавление ответов, создание нового тикета.
  - `custom_logout` — выход только POST‑запросом, с безопасным перенаправлением.
  - `profile_view` — страница профиля с общей статистикой (количество тикетов,
    отзывов, комментариев; импорт внешних моделей обернут в `try/except`).

Подобным образом **каждая функция и метод в коде снабжены
докстрингами и/или комментариями на русском**, чтобы было понятно:
что делает функция, какие принимает параметры и что возвращает.

## 3. Оптимизация и качество кода

- Везде, где это оправдано, используются:
  - `select_related` / `prefetch_related` для уменьшения количества запросов к БД,
  - кэширование (`cache_page`, `django.core.cache`) для главной и страниц,
  - индексы в моделях (`indexes` в `Meta`) для ускорения фильтрации.
- Логика, связанная с тяжелыми операциями (файлы, кэш, подсчеты), вынесена
  в отдельные методы/утилиты.
- Функции и классы документированы на русском, что упрощает дальнейшую поддержку.

Если потребуется более детальное документирование **каждой конкретной строки**
определенного файла, это можно оформить отдельным документом в папке `docs/`
(например, `docs/accounts_models_line_by_line.md`) — скажите, какие именно
файлы интересуют в первую очередь.

## 4. Развёртывание и работа на хостинге BEGET (исторические заметки)

Этот раздел основан на первоначальном описании, с которым проект был установлен
на хостинге **LTD BEGET**.

- Django был установлен системой автоматической установки CMS на стороне Beget.
- Рабочая директория виртуального окружения:
  `/home/d/dpitstudio/dpits-cms.ru/public_html/venv/`
- Для подключения к контейнеру использовалась команда:

```bash
ssh localhost -p222
```

- Активация виртуального окружения:

```bash
cd /home/d/dpitstudio/dpits-cms.ru/public_html
source venv/bin/activate
```

- Проверка `pip`:

```bash
which pip
# /home/d/dpitstudio/dpits-cms.ru/public_html/venv/bin/pip
```

- Установка дополнительных пакетов:

```bash
pip install <имя_пакета>
```

- Для перезапуска Passenger в каталоге проекта использовалась команда `touch`
на файле `restart.txt` в каталоге временных файлов:

```bash
cd /home/d/dpitstudio/dpits-cms.ru/public_html/HelloDjango/HelloDjango/tmp
touch restart.txt
```

Сейчас эта информация может отличаться от актуальной конфигурации сервера,
но логика остаётся той же: активировать виртуальное окружение, установить
зависимости и перезапустить WSGI‑процесс.
