# DPITS-CMS — Приложение `main`

## Описание приложения

Приложение `main` является основным модулем системы управления контентом DPITS-CMS. Оно отвечает за:

- **Глобальные настройки сайта** — контакты, логотип, SEO-параметры, статус "сайт закрыт"
- **Пользовательские страницы** — CMS-страницы с собственным контентом и SEO-настройками
- **Публичные представления** — главная страница, страницы контента, контакты, о нас, профиль пользователя, обработчики ошибок 404/500
- **Система логирования и аудита** — просмотр и управление логами ошибок и отладки через веб-интерфейс
- **Кэширование и контекстные процессоры** — меню навигации, данные сайдбара, SEO-контекст
- **Управление файлами на диске** — файловый менеджер через админ-панель Django (в отдельном модуле `admin_files.py`)

## Структура файлов и их описание

### `models.py` — Модели базы данных

Содержит все основные модели приложения для работы с базой данных.

#### `SingletonModel` (абстрактная модель)

Базовый класс для создания моделей-одиночек (singleton), которые могут иметь только один экземпляр в базе данных.

- **Метод `save()`**: Принудительно устанавливает `pk = 1` при сохранении, гарантируя единственность записи
- **Метод `load()`**: Возвращает единственный экземпляр модели, создавая его при необходимости

#### `SiteSettings` (модель настроек сайта)

Наследуется от `SingletonModel` и хранит глобальные настройки сайта.

**Поля модели:**
- **Контактная информация**: `phone1`, `phone2`, `email`, `address`
- **Визуальная часть**: `logo` (ImageField), `logo_text`, `slogan`, `motto` (CKEditor5Field), `short_description` (CKEditor5Field), `content` (CKEditor5Field)
- **Социальные сети**: `facebook`, `instagram`, `youtube`, `rutube`, `vk_video`, `telegram`, `vk`, `ok`
- **SEO-поля**: `seo_title`, `seo_keywords`, `seo_description`
- **Статус сайта**: `site_closed` (BooleanField), `closure_message` (TextField)
- **Временные метки**: `created_at`, `updated_at`

**Методы:**
- `__str__()`: Возвращает строковое представление "Настройки сайта"
- `clean()`: Валидация данных — требует `closure_message` при закрытом сайте и проверяет корректность email

#### `Page` (модель страниц)

Модель для пользовательских страниц сайта с поддержкой SEO и управления видимостью.

**Поля модели:**
- **Основное содержимое**: `title`, `slug` (уникальный), `content` (CKEditor5Field)
- **Управление отображением**: `show_in_menu`, `show_on_site`, `order`
- **SEO**: `seo_title`, `seo_keywords`, `seo_description`
- **Временные метки**: `created_at`, `updated_at`

**Методы:**
- `__str__()`: Возвращает заголовок страницы
- `get_absolute_url()`: Строит URL детальной страницы по slug
- `get_previous_page()`: Находит предыдущую страницу по порядку или дате
- `get_next_page()`: Находит следующую страницу по порядку или дате
- `display_title` (свойство): Возвращает SEO-заголовок, если задан, иначе обычный заголовок
- `clean()`: Запрещает использование зарезервированных slug (`admin`, `login`, `logout`, `password`)

#### `ManagedFile` (модель управления файлами)

Модель для управления файлами на диске через админ-панель Django.

**Поля модели:**
- **Основные**: `name`, `file_path` (уникальный, абсолютный путь), `category`, `description`
- **Настройки**: `is_active`, `is_text_file`, `encoding`, `auto_backup`, `max_backups`
- **Информация о файле**: `file_size`, `file_mtime`, `mime_type`, `file_permissions`
- **Содержимое**: `content` (для текстовых файлов)
- **Системные**: `last_checked`, `created_at`

**Методы и свойства:**
- `exists` (свойство): Проверяет наличие файла на диске
- `human_readable_size` (свойство): Форматирует размер в удобочитаемый вид (B, KB, MB, GB, TB)
- `refresh_file_info()`: Обновляет информацию о файле с диска
- `_check_if_text_file()`: Проверяет, является ли файл текстовым
- `clear_file()`: Очищает содержимое файла
- `create_backup()`: Создает резервную копию файла
- `cleanup_old_backups()`: Удаляет старые резервные копии сверх лимита
- `get_backup_list()`: Возвращает список резервных копий с метаданными
- `delete_file_from_disk()`: Удаляет файл с диска

### `views.py` — Представления (контроллеры)

Содержит все представления для публичной части сайта и служебные страницы.

#### `MaintenanceMixin` (миксин)

Миксин для проверки статуса обслуживания сайта. Переопределяет `dispatch()` и проверяет, не закрыт ли сайт.

#### `BaseView` (базовый класс)

Базовый класс для всех представлений, добавляет общий контекст:
- Загружает и кэширует `SiteSettings` на 5 минут
- Добавляет базовые SEO-данные в контекст
- Инициализирует логгер для отслеживания просмотров страниц

#### `IndexView` (главная страница)

Представление для главной страницы сайта:
- Получает рекомендуемые страницы и кэширует их на 10 минут
- Загружает последние 3 новости (если приложение `news` установлено)
- Формирует SEO-заголовок и описание
- Кэширует страницу на 15 минут

#### `PageDetailView` (детальная страница)

Представление для отображения детальной информации о странице:
- Фильтрует только активные страницы (`show_on_site=True`)
- Определяет предыдущую и следующую страницы
- Формирует SEO-данные
- Кэширует страницу на 10 минут

#### `LogStatsView` (статистика логов)

Представление для просмотра и управления лог-файлами (в основном `debug.log`).
- **Доступ**: только для `is_staff` (администраторов и персонала)
- **Функционал**:
    - Отображение размера файла и количества строк
    - Статистика по уровням логирования (INFO, WARNING, ERROR, DEBUG)
    - Предпросмотр последних 50 строк
    - Очистка лог-файла с созданием резервной копии
- **Шаблон**: `main/log_stats.html`

#### `ProfileView` (страница профиля)

Представление для страницы профиля пользователя:
- Требует аутентификации пользователя
- Перенаправляет на страницу логина, если пользователь не аутентифицирован

#### `ContactView` и `AboutView` (статические страницы)

Простые представления для страниц контактов и "О нас".

#### `custom_404_view` и `custom_500_view` (обработчики ошибок)

Функции-обработчики для ошибок 404 и 500, добавляют в контекст настройки сайта.

### `log_utils.py` — Утилиты логирования

Модуль с вспомогательными функциями для работы с лог-файлами.

**Функции:**
- `get_log_file_path()`: Получает или создает путь к файлу `debug.log`.
- `count_total_lines(log_file_path)`: Считает общее количество строк.
- `count_lines_by_category(log_file_path)`: Анализирует лог и считает количество записей по уровням (INFO, ERROR и т.д.).
- `get_log_file_info(log_file_path)`: Возвращает словарь с полной информацией о файле (размер, дата, статистика).
- `get_recent_log_lines(count, log_file_path)`: Читает последние N строк (эффективно для больших файлов).
- `clear_log_file(log_file_path, create_backup)`: Очищает файл, создавая бэкап в `logs/backups/`.
- `_format_file_size(size_bytes)`: Форматирование байтов в человекочитаемый вид.

### `admin.py` — Админ-панель для основных моделей

Содержит конфигурации админ-панели для моделей `SiteSettings` и `Page`.

#### `SiteSettingsAdmin`

Админ-панель для настроек сайта:
- Реализует singleton-режим (только одна запись)
- Запрещает создание дополнительных записей (`has_add_permission()`)
- Запрещает удаление настроек (`has_delete_permission()`)
- Группирует поля по логическим секциям
- Очищает кэш при сохранении

#### `PageAdmin`

Админ-панель для управления страницами:
- Отображает заголовок, slug, флаги видимости, порядок и дату обновления
- Разрешает инлайн-редактирование полей
- Настраивает поиск и фильтры
- Автоматически генерирует slug из заголовка
- Очищает кэш при сохранении

**Примечание**: Админ-интерфейс для `ManagedFile` находится в отдельном файле `admin_files.py` для избежания дублирования регистрации.

### `admin_files.py` — Админ-панель файлового менеджера

Содержит полноценный файловый менеджер для модели `ManagedFile`.

#### `ManagedFileAdmin`

Класс админ-панели для управления файлами:
- **Список файлов**: Отображает имя, категорию, путь, размер, статус, дату изменения и действия
- **Фильтры и поиск**: По категории, активности, типу файла, имени, пути, описанию
- **Форма редактирования**: Показывает основную информацию, настройки, содержимое файла, информацию о файле, предпросмотр, список резервных копий
- **Действия с файлами**: Обновление информации, создание бэкапа, очистка содержимого, удаление с диска
- **Массовые действия**: Обновление информации, создание бэкапов, очистка файлов, переключение активности, сканирование директорий
- **Кастомные URL**: Маршруты для действий с отдельными файлами и массовых операций

### `urls.py` — URL-маршруты приложения

Определяет все публичные URL-маршруты приложения:

- `""` — главная страница (`IndexView`, имя `main:index`)
- `"page/<slug:slug>/"` — детальная страница (`PageDetailView`, имя `main:page_detail`)
- `"contacts/"` — страница контактов (`ContactView`, имя `main:contacts`)
- `"about/"` — страница "О нас" (`AboutView`, имя `main:about`)
- `"profile/"` — страница профиля (`ProfileView`, имя `main:profile`)
- `"log-stats/"` — страница статистики логов (`LogStatsView`, имя `main:log_stats`)
- `"error/404/"` и `"error/500/"` — статические страницы ошибок

### `signals.py` — Сигналы Django

Содержит приемники сигналов для автоматической очистки кэша при изменениях в моделях.

#### `clear_site_settings_cache`

Очищает кэш настроек сайта при сохранении или удалении `SiteSettings`:
- Удаляет ключи: `site_settings`, `menu_pages`, `featured_pages`

#### `clear_pages_cache`

Очищает кэш страниц при сохранении или удалении `Page`:
- Удаляет ключи: `menu_pages`, `featured_pages`

#### `clear_managed_files_cache`

Очищает кэш управляемых файлов при изменениях в `ManagedFile`:
- Удаляет ключи: `managed_files_list`, `managed_files_active`, `managed_files_stats`

---

### `context_processors.py` — Контекстные процессоры

Добавляет общие данные во все шаблоны сайта.

#### `site_settings(request)`

Добавляет объект `SiteSettings` в контекст всех шаблонов:
- Кэширует настройки на 5 минут
- Делает доступным как `site_settings` в шаблонах

#### `menu_items(request)`

Формирует список страниц для меню навигации:
- Фильтрует страницы с `show_in_menu=True` и `show_on_site=True`
- Сортирует по полю `order`, затем по `title`
- Кэширует на 10 минут
- Делает доступным как `menu_pages` в шаблонах

#### `sidebar_data(request)`

Собирает данные для сайдбара:
- 3 последние новости (если приложение `news` установлено)
- 3 последних элемента портфолио (если приложение `portfolio` установлено)
- 3 последних одобренных отзыва (если приложение `reviews` установлено)
- Кэширует на 10 минут

#### `seo_context(request)`

Добавляет базовые SEO-данные в контекст:
- `default_seo_title`, `default_seo_description`, `default_seo_keywords`

### `apps.py` — Конфигурация приложения

Содержит класс `MainConfig` для настройки приложения:

- `name = "main"` — имя приложения
- `verbose_name = "Основные настройки"` — человекочитаемое имя

## Исправленные ошибки

В процессе проверки и исправления были устранены следующие проблемы:

1. **Отсутствующий импорт `shutil` в `models.py`**
   - Проблема: Метод `create_backup()` использовал `shutil.copy2()`, но модуль не был импортирован
   - Решение: Добавлен импорт `import shutil` в начало файла

2. **Неправильный метод получения объекта в `admin_files.py`**
   - Проблема: Использовался несуществующий метод `self.get_object(request, file_id)`
   - Решение: Заменен на `get_object_or_404(ManagedFile, pk=file_id)` из `django.shortcuts`

3. **Дублирующая регистрация модели `ManagedFile`**
   - Проблема: Модель `ManagedFile` регистрировалась и в `admin.py`, и в `admin_files.py`, что вызывало ошибку `AlreadyRegistered`
   - Решение: Удалена регистрация из `admin.py`, оставлена только в `admin_files.py`

## Установка и использование

### Требования

- Python 3.8+
- Django 4.0+
- django-ckeditor-5
- Pillow

### Установка

```bash
# Установка зависимостей
pip install -r requirements.txt

# Применение миграций
python manage.py migrate

# Создание суперпользователя
python manage.py createsuperuser
```

### Использование админ-панели

- `/admin/main/sitesettings/` — создание и редактирование глобальных настроек сайта
- `/admin/main/page/` — управление пользовательскими страницами
- `/admin/main/managedfile/` — файловый менеджер для управления файлами на диске

### Публичные URL

- `/` — главная страница
- `/page/<slug>/` — детальные страницы контента
- `/contacts/` — страница контактов
- `/about/` — страница "О нас"
- `/profile/` — страница профиля пользователя (требует аутентификации)
- `/log-stats/` — статистика логов (требует прав персонала)
