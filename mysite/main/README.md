## DPITS-CMS (приложение `main`) — описание и структура

### Назначение приложения `main`

Приложение `main` отвечает за:
- **глобальные настройки сайта** (контакты, логотип, SEO, статус "сайт закрыт");
- **пользовательские страницы** (CMS-страницы со своим контентом и SEO);
- **публичные представления** (главная, страницы, контакты, о нас, профиль, 404/500);
- **кэширование и контекстные процессоры** (меню, сайдбар, SEO);
- **управление файлами на диске через админку** (в отдельном модуле `admin_files.py`).

Ниже приведено **описание всех основных файлов и их работы**.

---

### Файл `models.py` — модели базы данных

Содержит все основные модели приложения:

- **`SingletonModel`**
  - Абстрактная база для моделей‑одиночек (singleton).
  - При сохранении всегда принудительно устанавливает `pk = 1`, а метод `load()` возвращает (создаёт при необходимости) единственный экземпляр.

- **`SiteSettings`**
  - Наследуется от `SingletonModel` и хранит **глобальные настройки сайта**:
  - Контакты: телефоны, email, адрес.
  - Визуальная часть: логотип (`ImageField`), текст логотипа, слоган, девиз, краткое описание, основной контент (через `CKEditor5Field`).
  - Ссылки на **социальные сети** (Facebook, Instagram, YouTube, Rutube, VK, OK, Telegram и др.).
  - **SEO-поля**: `seo_title`, `seo_keywords`, `seo_description`.
  - Статус сайта: флаг `site_closed` и текст `closure_message`, который показывается при закрытии сайта.
  - Метки времени: `created_at`, `updated_at`.
  - Метод `__str__()` возвращает человекочитаемое имя "Настройки сайта".
  - Метод `clean()`:
    - Требует указать `closure_message`, если сайт помечен как закрытый.
    - Выполняет простую проверку корректности email.

- **`Page`**
  - Модель **пользовательских страниц** сайта.
  - Основные поля:
    - `title` — заголовок страницы;
    - `slug` — URL‑часть (уникальная);
    - `content` — HTML/текст контента через `CKEditor5Field`.
  - Управление отображением:
    - `show_in_menu` — показывать ли страницу в меню;
    - `show_on_site` — активна ли страница;
    - `order` — порядок сортировки в меню/списках.
  - SEO:
    - `seo_title`, `seo_keywords`, `seo_description`.
  - Метки времени: `created_at`, `updated_at`.
  - **Мета**:
    - `verbose_name = "Страница"`, сортировка по `order`, затем по `title`.
  - Методы:
    - `__str__()` — возвращает `title`.
    - `get_absolute_url()` — строит URL детальной страницы по `slug`.
    - `get_previous_page()` и `get_next_page()` — находят соседние страницы по `order` и дате создания.
    - Свойство `display_title` — возвращает SEO‑заголовок, если он задан, иначе обычный `title`.
    - `clean()` — запрещает использовать зарезервированные `slug` (`admin`, `login`, `logout`, `password`).

- **`ManagedFile`**
  - Модель для **управления файлами на диске через админку**.
  - Основные поля:
    - `name` — отображаемое имя файла.
    - `file_path` — **абсолютный путь** к файлу в ОС (уникальный).
    - `category` — категория файла (лог, конфиг, шаблон, статика, медиа, БД, бэкап, другое).
    - `description` — текстовое описание.
    - `content` — текстовое содержимое (для текстовых файлов).
    - `is_text_file` — флаг "текстовый/бинарный".
    - `encoding` — кодировка файла.
    - `is_active` — отслеживать ли файл.
    - `auto_backup` и `max_backups` — настройки автосоздания бэкапов.
  - Служебные/автоматические поля:
    - `file_size` — размер файла в байтах.
    - `file_mtime` — время последнего изменения файла.
    - `mime_type` — MIME‑тип.
    - `last_checked` — время последней проверки.
    - `created_at` — время создания записи.
    - Индексы по `category`, `is_active`, `file_path`.
  - Методы и свойства:
    - `clean()`:
      - требует непустой `file_path`;
      - проверяет уникальность пути;
      - при создании убеждается, что файл существует.
    - `save()` — при сохранении, если файл существует, вызывает `_update_file_info()`.
    - `_update_file_info()` — обновляет `file_size`, `file_mtime`, `mime_type`, по необходимости определяет тип файла и читает содержимое (для текстовых файлов до 5 МБ).
    - `_read_file_content()` — пытается прочитать файл с несколькими кодировками (utf‑8, cp1251, cp866 и др.), сохраняет найденную; при неудаче помечает файл как бинарный.
    - `_detect_if_text_file()` — грубая проверка “текстовый или нет” через пробное чтение в utf‑8.
    - `get_absolute_url()` — ссылка на страницу изменения файла в админке.
    - Свойство `exists` — проверяет наличие файла на диске.
    - Свойство `human_readable_size()` — форматирует размер в байты/КБ/МБ/ГБ/ТБ.
    - Свойство `file_permissions()` — возвращает текущие права доступа в восьмеричном виде.
    - `create_backup()` — создаёт резервную копию файла в `MEDIA_ROOT/file_backups/<category>/...`, чистит старые копии через `_cleanup_old_backups()`.
    - `clear_file()` — очищает содержимое файла (текстовые — пустая строка, бинарные — нули), при необходимости создаёт бэкап.
    - `delete_file_from_disk()` — удаляет файл с диска и обновляет состояние записи.
    - `refresh_file_info()` — принудительно перечитывает информацию о файле с диска.
    - `get_backup_list()` — возвращает список резервных копий с размерами и датами.
    - Вспомогательное `_format_size()` — форматирует размер, как и `human_readable_size`.

### Файл `views.py` — представления (контроллеры)

Содержит все основные вьюхи публичной части:

- **`MaintenanceMixin`**
  - Переопределяет `dispatch()` всех наследников.
  - Загружает `SiteSettings` и, если сайт помечен как закрытый и пользователь **не** `is_staff`, возвращает шаблон `"main/site_closed.html"` с сообщением.

- **`BaseView` (наследуется от `TemplateView`)**
  - Базовый класс для всех страниц, добавляет общий контекст:
    - загружает и кэширует `SiteSettings` под ключом `"site_settings"` на 5 минут;
    - выставляет **базовый SEO‑контекст**: `page_title`, `meta_description`, `meta_keywords` с разумными значениями по умолчанию.

- **`ProfileView` (наследники: `MaintenanceMixin`, `BaseView`, `TemplateView`)**
  - Страница профиля пользователя (`template_name = "main/profile.html"`).
  - В `dispatch()`:
    - если пользователь не аутентифицирован, перенаправляет на страницу логина (`accounts:login`).
  - `get_context_data()`:
    - добавляет заголовок “Профиль”, описание и объект текущего пользователя.

- **`IndexView` — главная страница**
  - Шаблон: `"main/index.html"`.
  - В `get_context_data()`:
    - вытаскивает рекомендованные страницы (`Page` с `show_on_site=True`) и кэширует список `featured_pages` на 10 минут;
    - пытается подгрузить последние 3 новости из `news.News` (сначала фильтр `is_active=True`, затем fallback на все новости, если поле отсутствует);
    - формирует SEO‑заголовок для главной с учётом `SiteSettings.logo_text` и `seo_title`;
    - формирует `meta_description`, очищая HTML из `short_description` и обрезая до 160 символов, либо использует `seo_description`.
  - `dispatch()` обёрнут в декораторы:
    - `cache_page(15 минут)` — кэширует всю страницу;
    - `vary_on_cookie` — различает кеш по кукам пользователя.

- **`PageDetailView` (`DetailView` для модели `Page`)**
  - Отдаёт детальную страницу по `slug` (`/page/<slug>/`).
  - `get_queryset()` фильтрует только `show_on_site=True`.
  - В `get_context_data()`:
    - подгружает `SiteSettings`;
    - определяет предыдущую и следующую страницы через методы модели `Page`;
    - строит `page_title` с учётом `SiteSettings.logo_text`;
    - `meta_description` берётся из `seo_description` или из обрезанного контента (без HTML‑тегов);
    - добавляет в контекст `meta_keywords`, `prev_page`, `next_page`.
  - `dispatch()` кэшируется на 10 минут и учитывает куки.

- **`ContactView` и `AboutView`**
  - Простейшие `TemplateView` с шаблонами `"main/contacts.html"` и `"main/about.html"`.
  - Загружают `SiteSettings` и формируют заголовок/описание (для "О нас" также может использоваться `short_description` из настроек).

- **`custom_404_view` и `custom_500_view`**
  - Функции‑обработчики ошибок 404 и 500.
  - Подмешивают в контекст `SiteSettings` и человекочитаемые SEO‑заголовки/описания.

### Файл `admin.py` — админ-панель (основные модели)

Содержит конфигурации админки **для настроек сайта и страниц**:

- **`SiteSettingsAdmin`**
  - Регистрируется как singleton‑настройки сайта.
  - Запрещает создание более одной записи (`has_add_permission()` возвращает False, если запись уже есть).
  - Запрещает удаление настроек (`has_delete_permission()` всегда False).
  - Разбивает поля по логическим группам (основное, контакты, соцсети, статус, дополнительный контент, SEO).
  - При сохранении очищает кэш `site_settings`, `menu_pages`, `featured_pages`.

- **`PageAdmin`**
  - Управление страницами `Page`:
  - В списке показывает заголовок, slug, флаги видимости, порядок и дату обновления.
  - Разрешает инлайн‑редактирование `show_in_menu`, `show_on_site`, `order`.
  - Настраивает поиск по заголовку, slug и содержимому.
  - Автоматически подставляет `slug` из `title`.
  - При сохранении очищает кэш меню и рекомендованных страниц.
  - Подключает дополнительный CSS (`admin/css/pages.css`).

> **Важно:** админ‑интерфейс для `ManagedFile` вынесен в отдельный файл `admin_files.py`, чтобы избежать дублирования и разделить “общую” админку и файловый менеджер.

---

### Файл `admin_files.py` — админка файлового менеджера

Здесь регистрируется и настраивается **полноценный файловый менеджер** для модели `ManagedFile`:

- Класс **`ManagedFileAdmin`**:
  - Список (`list_display`) показывает:
    - имя файла с иконкой (текст/бинарный),
    - категорию с цветным бейджем,
    - сокращённый путь,
    - размер,
    - статус (активен/неактивен/отсутствует),
    - последнее изменение в человекочитаемом виде,
    - колонку с действиями (просмотр, обновление, бэкап, очистка).
  - Фильтры и поиск по имени, пути, описанию и содержимому.
  - В форме редактирования:
    - отображает основные поля и флаги,
    - показывает подробную информацию о файле (размер, права, MIME, дата изменения, кодировка),
    - даёт предпросмотр первых 15 строк текста,
    - выводит список резервных копий.
  - Переопределяет `save_model()`:
    - при изменении текстового файла проверяет размер (до 5 МБ),
    - при необходимости создаёт резервную копию,
    - записывает содержимое обратно в файл на диске.
  - `get_urls()` добавляет дополнительные маршруты админки для:
    - обновления информации о конкретном файле;
    - создания бэкапа;
    - очистки содержимого;
    - удаления файла с диска.
  - Действия (actions) для массива файлов:
    - обновить информацию (`refresh_selected_files`);
    - создать бэкапы (`create_backup_selected`);
    - очистить файлы с подтверждением (`clear_selected_files`);
    - переключить флаг активности (`toggle_active_selected`);
    - просканировать директории на наличие логов/конфигов (`scan_logs_directory`).
  - Подключает свои стили и скрипты (`css/admin-file-manager.css`, `js/admin-file-manager.js`).

### Файл `urls.py` — URL‑маршруты приложения

Определяет все публичные URL‑маршруты приложения `main`:

- `""` — главная страница, `IndexView`, имя `main:index`.
- `"page/<slug:slug>/"` — детальная страница `PageDetailView`, имя `main:page_detail`.
- `"contacts/"` — `ContactView`, имя `main:contacts`.
- `"about/"` — `AboutView`, имя `main:about`.
- `"profile/"` — `ProfileView`, имя `main:profile` (доступно после логина).
- `"error/404/"` и `"error/500/"` — статические странички ошибок для проверки шаблонов.

### Файл `signals.py` — сигналы Django

Содержит приёмники сигналов `post_save` и `post_delete`:

- **`clear_site_settings_cache`**:
  - Вызывается при изменении `SiteSettings`.
  - Удаляет ключи кэша: `site_settings`, варианты для разных вьюх, а также `menu_pages`, `featured_pages`.

- **`clear_pages_cache`**:
  - Срабатывает при сохранении/удалении страниц `Page`.
  - Очищает кэш меню и рекомендованных страниц.

- **`clear_managed_files_cache`**:
  - Универсальный приёмник, вызывается для всех моделей, но внутри проверяет, что `sender.__name__ == "ManagedFile"`.
  - При изменении управляемых файлов очищает кэш списков и статистики файлового менеджера.

---

### Файл `context_processors.py` — контекстные процессоры

Добавляет общие данные во все шаблоны:

- **`site_settings(request)`**
  - Возвращает объект `SiteSettings` (кэшируется на 5 минут под ключом `"site_settings"`).
  - Делает настройки сайта доступными как `site_settings` во всех шаблонах.

- **`menu_items(request)`**
  - Формирует список страниц для меню (`Page` с `show_in_menu=True` и `show_on_site=True`).
  - Кэширует результат под ключом `"menu_pages"` на 10 минут.

- **`sidebar_data(request)`**
  - Собирает данные для сайдбара:
    - 3 последние новости (`news.News` с `is_active=True`, если приложение есть);
    - 3 последних элемента портфолио (`portfolio.PortfolioItem` со статусом `published`);
    - 3 последних одобренных отзыва (`reviews.Review` со статусом `approved`).
  - Все данные кэшируются под ключом `"sidebar_data"` на 10 минут.

- **`seo_context(request)`**
  - Загружает `SiteSettings` и возвращает значения по умолчанию для SEO:
    - `default_seo_title`, `default_seo_description`, `default_seo_keywords`.

### Файл `apps.py` — конфигурация приложения

- Класс **`MainConfig`**:
  - `name = "main"`, `verbose_name = "Основные настройки"`.
  - `default_auto_field = "django.db.models.BigAutoField"`.
  - В методе `ready()` подключает модуль `signals` (через `try/except`, чтобы избежать падения при ошибке импорта).

### Файл `admin_files.py` vs `admin.py` — как они связаны

- `admin.py`:
  - содержит админку только для **`SiteSettings`** и **`Page`**;
  - не регистрирует `ManagedFile`, чтобы избежать двойной регистрации.

- `admin_files.py`:
  - содержит **единственную** актуальную регистрацию `ManagedFileAdmin` для `ManagedFile`;
  - реализует весь функционал файлового менеджера (просмотр, редактирование, бэкапы, очистка, сканирование).

Таким образом, ошибки вида `AlreadyRegistered: The model ManagedFile is already registered` исключены.

### Шаблоны и статика

- **Шаблоны (`templates/main/`)**:
  - `index.html` — главная;
  - `page_detail.html` — страница `Page`;
  - `contacts.html`, `about.html`, `profile.html` — соответствующие статические вьюхи;
  - `404.html`, `500.html` — пользовательские обработчики ошибок;
  - `site_closed.html` — страница “Сайт на обслуживании”.

- **Шаблоны админки (`templates/admin/main/`)**:
  - `managedfile_change_form.html` — кастомная форма изменения файла;
  - `managedfile_change_list.html` — список файлов;
  - `confirm_clear_files.html` — подтверждение массовой очистки содержимого.

- **Статика (`static/`)**:
  - CSS и JS для файлового менеджера (`css/admin-file-manager.css`, `js/admin-file-manager.js`);
  - возможные дополнительные стили/скрипты для публчной части и админки.

### Установка, запуск и использование (кратко)

- **Установка**:
  - Python 3.8+, Django 4.0+, `django-ckeditor-5`, Pillow.
  - Установка зависимостей: `pip install -r requirements.txt`.
  - Миграции: `python manage.py migrate`.
  - Создание суперпользователя: `python manage.py createsuperuser`.

- **Админка**:
  - `/admin/main/sitesettings/` — создание и редактирование глобальных настроек.
  - `/admin/main/page/` — управление страницами.
  - `/admin/main/managedfile/` — файловый менеджер (через `admin_files.py`).

- **Публичная часть**:
  - `/` — главная страница.
  - `/page/<slug>/` — любые CMS‑страницы.
  - `/contacts/`, `/about/`, `/profile/` — служебные и пользовательские страницы (профиль требует аутентификации).
